# Working stream — `uiconfig-dom`

## Summary

- **What:** a new package, `uiconfig-dom`: a plain-DOM renderer for uiconfig.js configs, with no Tweakpane and no React.
- **Why now (2026-11-18):** threepipe's example card (repalash/threepipe#192) uses `UiConfigForm` from `@threepipe/plugin-tweakpane-editor`. Through that bundle, every example page loads the editor and plugin-tweakpane: 198 KB gzip. The form itself (UiConfigForm, its CSS, the icons, the tooltip code) is about 11 KB gzip without tippy.js (26.5 KB with tippy.js, which is 15.6 KB of it). Measured with a Vite library build, threepipe external.
- **Where it starts:** threepipe `plugins/tweakpane-editor/src/ui/UiConfigForm.ts` (on the branch `claude/examples-action-bar` of repalash/threepipe, PR #192), with its `UiConfigForm.css`, `lucideIcons.ts`, and the tests in `tests/unit/ui-config-form.test.ts`.
- **Status:** steps 1 to 7 are done on this branch (uiconfig.js 0.5.0, uiconfig-tweakpane 2.3.0, uiconfig-blueprint 0.1.0-dev.20, uiconfig-dom 0.1.0, and a website example). Not published. Step 8 (threepipe) comes after the release.

## Decisions (Palash, 2026-11-18)

1. **Tooltips: a hook, no dependency.** tippy.js is only used for the hover tooltips of the `bar` and `stack` buttons (the popover is the form's own code). uiconfig-dom has a `tooltip(el, text)` hook; the default is the native `title`. threepipe's editor passes its tippy.js tooltips through the hook, so it looks the same. uiconfig-dom depends only on `uiconfig.js` and `ts-browser-helpers`.
2. **Many refresh listeners: in this work.** It is a change in uiconfig.js core (see the plan, step 1).
3. **threepipe re-exports it from its core bundle** (`threepipe`), like uiconfig.js. The example card imports it from `threepipe`; the examples no longer load the editor and plugin-tweakpane for the card. `@threepipe/plugin-tweakpane-editor` keeps exporting `UiConfigForm` (from threepipe) and sets the tippy.js tooltip hook.
   - The re-export in threepipe gets a TODO comment: move uiconfig-dom out of the core; revisit when the module bundling and packaging of `@threepipe/core` change.
4. uiconfig.js loads once: uiconfig-dom keeps `uiconfig.js` and `ts-browser-helpers` external (`externalDeps`, like uiconfig-tweakpane); threepipe's build rewrites them to `threepipe`.

## The plan

1. **Many refresh listeners (uiconfig.js core).** Done. Today a config has one `uiRefresh` slot, and each renderer assigns it, so a form and a Tweakpane panel on the same config replace each other's.
   - Callers keep calling `config.uiRefresh?.(deep, mode, delay)`.
   - Renderers register with an API (for example `UiConfigMethods.AddRefreshListener(config, fn)` returning a remove function); `config.uiRefresh` calls every listener.
   - Code that assigns `config.uiRefresh = fn` keeps working (threepipe forwards refreshes that way in `AnimationObjectPlugin`, and its tests assign it); assigning `undefined` removes only that assigned function.
   - `disposeUiConfig` removes only the listener of the renderer that disposes.
   - Update the renderers in this repository to the API: uiconfig-tweakpane, uiconfig-blueprint, uiconfig-react. Tests in uiconfig.js.
2. **One base class:** the renderer extends `UiConfigRendererBase` and uses its `methods` (`PerformAction`, the disabled check), not its own copies. It keeps its own value setter (decision 5). Done.
3. **No threepipe imports:** import from `uiconfig.js` and `ts-browser-helpers`. Colours: `--ucf-*` variables, with the `--tp-*` names as fallbacks so a Tweakpane theme still applies. Done.
4. **Aliases:** handle the `select` and `vector` aliases. Done.
5. **Tooltip hook** (decision 1) and **icons:** the Lucide set (ISC, with attribution) stays with the form as `lucideIcons` / `lucideIcon(name)`, and apps can add icons by name. Done.
6. **Package:** `packages/uiconfig-dom` (README, CHANGELOG, LICENSE, a vite build like uiconfig-tweakpane with `externalDeps`), the tests from threepipe, docs, and a page on the website. Done.
7. **Release:** versions and CHANGELOG entries for uiconfig.js, uiconfig-tweakpane, uiconfig-blueprint and uiconfig-dom. Publishing (push to master, then approval of `npm-publish`) is Palash's call. Done.
8. **threepipe (after the release):** bump uiconfig.js and the renderers; re-export uiconfig-dom from `threepipe` (with the TODO of decision 3); the editor re-exports it and passes its tippy.js tooltips; the example card imports it from `threepipe`; remove the editor and plugin-tweakpane from the import maps of the examples that only had them for the card.

## Decision 5 (Palash, 2026-11-18): the form's `_set` and `_action` against `methods.setValue` and `PerformAction`

Option 1 below: fix `PerformAction` in uiconfig.js; the form runs its buttons through `methods.performAction` and uses `GetBaseProps` for the hidden and disabled state, and keeps its own value setter (`_set`). The uiconfig-dom README says why (Design notes). Done: `PerformAction` reads undo and redo at replay, keeps the undo of a redo run, and takes an `onPending` callback (for the spinner).

The question, as it was asked: plan step 2 says the form uses `methods.setValue` and `PerformAction` instead of its own copies. They are not copies: the form's code does things that uiconfig.js does not, and threepipe's tests check them. With `UiConfigMethods` as it is now (checked in a scratch test):

- `PerformAction`, a button that returns an undo function: undo, redo, undo leaves the object of the redo (`[2]`; the form: `[]`). Its redo runs the action again but drops the undo function that this run returns.
- `PerformAction`, an action whose undo replaces its redo (threepipe `EntityComponentPlugin.addComponent`): undo, redo gives `[2]` (the form: `[1]`). It binds `res.undo` and `res.redo` when it records the step, not when it replays it.
- `SetValue`, three committed edits of one field in a row, one undo: `3` (the form merges them into one step: `1`). uiconfig.js merges only while `last` is false, within 2 s; the form merges the same field within 1 s or in one gesture.
- `SetValue` calls `onChange` of the config and its `parentOnChange`, which only a renderer that draws the parent sets. The form calls the `onChange` of each parent folder in the form without setting `parentOnChange` (it would replace the Tweakpane one on a shared config). With `SetValue`, a folder `onChange` (for example `material.setDirty()` in threepipe's ui-config-form example) is not called when only the form draws the folder.
- `SetValue` has no hook for the undo and redo of a dropdown (the form calls `onStructureChange` after them, to make the form again), and its undo refreshes through `uiRefresh` after a promise and a frame (the form refreshes at once; tests check the value right after `undo()`).

Options:
1. Fix `PerformAction` in uiconfig.js (read the undo and redo when replaying; keep the undo function that a redo returns; tell the caller when the action returns a promise, for the spinner). It is a bug fix that the Tweakpane and Blueprint buttons get too. The form then uses `methods.performAction`. For values the form keeps its own `_set` (its undo merge, the folder chain, the structure hook) and uses `GetBaseProps` for the disabled check.
2. Also extend `SetValue` in uiconfig.js (an `onUndoRedo` hook for the structure change; a way to dispatch to the parent folders of the caller), and take the form's merge rule into `setValueUndoCommand` or keep uiconfig.js's. Larger change in core, and the undo steps of the form change.
3. The form uses `methods.setValue` and `performAction` as they are, and loses the behaviours above (threepipe's tests for them change).

## Follow-up

- Align `UiConfigMethods.SetValue` with what the form's `_set` does, so that the form can use `methods.setValue`: a hook after the undo and redo of a step (the form calls `onStructureChange` there, and refreshes at once), a way to dispatch the change to the parent folders of the caller without setting `parentOnChange` on shared configs, and one undo merge rule (the form merges the same field within 1 s or in one gesture; uiconfig.js merges while `last` is false, within 2 s).
- The API docs of the website (one TypeDoc site) and its agent docs (`llms.txt`) do not include uiconfig-dom yet: `website/typedoc.json`, `scripts/docs-finish.mjs`, `scripts/llms.mjs`, `scripts/assemble-pages.mjs` and `src/docs/docs.js` list the three packages.
- uiconfig-tweakpane: a refresh of an input whose value changed outside it sets the value back through the binding (an `onChange` with the same value, or a value snapped to the `stepSize` with float noise: 3.3 becomes 3.3000000000000003 with a step of 0.1). Seen in the dom-form example; it happens without uiconfig-dom too.

## Running detail

- `uiRef` stays one slot per config: two renderers that both use it (Tweakpane and Blueprint) still cannot draw the same config (a refresh in one reads the other's `uiRef`; it was so before). The form does not use `uiRef`.

- uiconfig-dom: ES module only (`dist/index.mjs`, plus `lib/esm`), no UMD or CommonJS bundle, since those are deprecated in the other packages. Its refresh: no frame loop of its own; `immediate` refreshes at once, the other modes in one requested animation frame; a listener of a frame event (uiconfig.js `RunAtEvent` for a `dispatchMode`) also requests a frame. `refresh()` is unchanged (threepipe's example card calls it after each viewer frame).
- uiconfig-dom size (dist/index.mjs, as built: identifiers minified, whitespace kept, as Vite does for an ES library): 47.2 KB, 14.6 KB gzip; minified by the app's bundler: 36.3 KB, 12.0 KB gzip. About half of it is the icons and the stylesheet string.
