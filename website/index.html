uiconfig.js

Describe a UI as plain objects bound to your data. A renderer turns the description into a live panel: Tweakpane, Blueprint, or one you write.

The config is data, so the code that defines it has no dependency. Only the page that shows the panel imports a renderer.

npm install uiconfig-tweakpane

Config of this panel

One config, any renderer

Renderers are separate packages, and a config does not import any of them. The same config works as a small debug panel in Tweakpane and as an app inspector in Blueprint. Both panels below edit one light object: change a value in one, and the other follows.

The config

Each panel gets its own copy, createLightConfig(light), because a renderer keeps its state in the config. The onChange of one calls uiRefresh(true) on the other.

Three ways to write it

Put the config next to the data in an object, build it in a class, or let TypeScript decorators generate it from the fields. Each tab shows the code that renders the panel next to it.

Render any of them with

// or 'uiconfig-blueprint'
import {UI} from 'uiconfig-tweakpane'

const ui = new UI()
ui.appendChild(data.uiConfig)

Decorators need "experimentalDecorators": true in tsconfig.json.

Components

The type of a config picks the component. Some types have aliases. Both renderers support the common set; Tweakpane adds a few.

Color and vector components create their values with the classes in ui.THREE: set it to three.js Color, Vector2, Vector3 and Vector4, as this page does. The uiImage decorator has no component in these renderers yet; threepipe adds its own image and texture inputs.

    With three.js

    threepipe, a three.js framework, builds its UI with uiconfig. The viewer, its plugins, objects and materials carry a uiConfig, and the editor renders them with uiconfig-tweakpane or uiconfig-blueprint.

    import {Color, Vector2, Vector3, Vector4} from 'three'
import {UI} from 'uiconfig-tweakpane'

const ui = new UI()
ui.THREE = {Color, Vector2, Vector3, Vector4} // color and vector inputs edit these objects
viewer.uiConfig.children.forEach((child) => ui.appendChild(child))

    Install

    npm install uiconfig-tweakpane   # Tweakpane renderer
npm install uiconfig-blueprint   # Blueprint renderer (React)
npm install uiconfig.js          # types and decorators, for TypeScript

    The packages are ES modules for a bundler such as Vite, webpack or esbuild. Their dist/index.mjs imports its dependencies instead of bundling them, so the app keeps one copy of uiconfig.js, Tweakpane and React. JavaScript code needs only a renderer; TypeScript code adds uiconfig.js for the types and decorators.

    A page without a bundler can load the UMD build from a CDN. It includes every dependency and is legacy: the next major version removes it.

    <script src="https://unpkg.com/uiconfig-tweakpane"></script>
<script>
  const ui = new window['uiconfig-tweakpane'].UI() // uiconfig-blueprint: new bpui.UI()
  ui.appendChild({type: 'button', label: 'Click me', onClick: () => console.log('clicked')})
</script>
